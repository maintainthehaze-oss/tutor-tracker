# 2026-10-11 — Header overflow at 640 px fixed (Claude Code, Fable 5.1)

## What
Pre-existing (not from Slice E): at a 481–768 px viewport with data loaded and the backup pill showing, `.app-header` was a single non-wrapping flex row, so `.header-right` reached x=865 and the page scrolled sideways.

## Change (one commit)
- `protected/styles.css`, `@media (max-width: 768px) and (min-width: 481px)` block only:
  `.app-header { flex-wrap: wrap }`, `.header-center { order: 1; flex-basis: 100% }`, `.live-stats { flex-wrap: wrap; justify-content: center }`.
  Logo + search/theme/settings buttons share row one; the three stat pills take a centred second row.
- `tests/this-week.test.cjs`, "static: narrow layout pins": +3 assertions pinning those three rules inside the tablet block.

## Verification
- `node --test` 244/244, 0 fail. Static guard PASS. `node --check protected/js/*.js` clean.
- Mutation: `flex-basis: 100%` → `50%` made the new pin fail ("stat pills take their own row under 768 px"); restored.
- OBSERVED in the built-in browser at 640×900 on the fabricated preview (dark, data loaded, backup pill visible): `document.documentElement.scrollWidth` 640 = viewport; `.header-right` x 290–625; pills at y=128 spanning x 103–537; `.app-header` computed `flex-wrap: wrap`.
- NOT observed: light theme, 481 px and 768 px edges, real data. Under 480 px the existing column layout is unchanged.
