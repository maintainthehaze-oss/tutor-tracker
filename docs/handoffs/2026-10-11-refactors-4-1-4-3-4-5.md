## 4.1 One money path — RE-SCOPED (ruling, veto if wrong)
The roadmap said "make computeMetrics delegate to reportModel and delete the copies". Not done as written:
- `computeMetrics` reads today's working records (`repository.read()`, no historical rows) with today's families.
- `reportModel.metrics` reads working + 1,652 archive historical rows, with snapshot-time clients for legacy rows.
- Its only callers are Owed (`computeOwedByFamily`) and family payment intake / statements (`payments.js`).
  Delegating would put historical rows into statements and group legacy rows by snapshot-time families.
- `tests/slice3/read-guard.test.cjs` already forbids reports from calling `computeMetrics`: two ledgers by design.
- The money fixture keeps `historical: []`, so the "paths agree" pin could never see this difference.
Done instead: the arithmetic (filters, totals, even per-family split) is ONE function, `App.moneyRollup`
(`app-core.js`); both ledgers call it with their own rows and client lookup. Sessions Totals row unchanged
(it sums the rows on screen and already uses `App.revenueAmount`).
Real data, aggregates only: historical has 0 unpaid completed rows, so Owed would not have moved either way.
